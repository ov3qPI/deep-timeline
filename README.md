# ICS (iCalendar) event import
Use Event Data → IMPORT ICS to select a .ics file with Android’s document picker. Each VEVENT contributes its DTSTART instant and summary; DTEND and DURATION are ignored, so Deep Timeline imports no duration. UTC timestamps retain UTC; supported TZID timestamps use their IANA timezone; floating times and all-day dates use the device timezone, with all-day dates starting at midnight. Invalid or cancelled VEVENT entries appear in the selection checklist but cannot be selected. Existing UID values map to stable imported UUIDs for repeat imports. RRULE and RDATE are not expanded: only the supplied DTSTART is imported. Descriptions, alarms, and reminders are not imported. The normal preview, duplicate detection, and atomic SQLite import transaction are reused. The 64 MiB input and 100,000-event limits remain in force. ICS parsing is covered by tests/IcsTests.kt.
# JSON event import/export and checklist
The transfer icon in the toolbar opens Import JSON, Import ICS, Export Events JSON, and Export JSON Template. Both event import and event export show every candidate in a scrollable checklist before any data changes. The preview offers ALL, NONE, and INVERSE, and an X that cancels without writing. Invalid incoming rows are shown but cannot be checked; unchanged and duplicate records are unchecked by default. Existing UUIDs are flagged UPDATE EXISTING; selecting them replaces that record only. Import writes all selected entries atomically in one SQLite transaction. Export writes exactly the selected records through Android’s Storage Access Framework, which requires no storage permission. Selecting no events exports a valid empty events array. The template supplies editable BCE, prehistoric, and longitude examples. Full nanosecond instants, UUIDs, civil dates, interpretation modes, coordinates, zone IDs, and creation/update metadata round-trip. Defaults for manually authored entries are midnight and UTC, with UUID generation when absent. See docs/JSON_Transfer_v20261108T045322Z.md.
## Android-derived event label typography
Event names use the actual Android native TextView default text size and typeface from the app theme, expressed as physical pixels after the Android font-size/accessibility setting is applied. The Canvas does not use a hard-coded dp font size. The renderer reads Paint ascent, descent, leading and fontSpacing to derive a minimum baseline separation, selection tolerance, baseline placement and offscreen culling. When configuration changes, it re-reads font metrics, measures all event names again for horizontal panning, invalidates geometry, and recomputes the hyperflow arrangement using the new spacing. All events retain their original timestamps and the layout remains continuous.
## BCE and prehistoric events
The Date field accepts a negative year to represent BCE: -44-03-15 means 44 BCE, -2500-01-01 means 2500 BCE, and -200000-01-01 means 200000 BCE. The user-visible calendar has no year zero: -1 is 1 BCE and 1 is 1 CE. Underlying java.time astronomical years include zero, so the app converts negative input using astronomical year = 1 + entered BCE year. The event remains stored as signed epoch seconds plus nanoseconds; timeline sorting, zoom and hyperflow are unchanged. Date/time uses a proleptic Gregorian calendar throughout, not a reconstructed prehistoric or Roman Julian calendar; exact day and time for ancient events must be supplied with this convention in mind. Local civil timezone rules for ancient dates are extrapolations from modern geographical rules, not evidence of historic clock practice. The editor preserves typed BCE convention in stored civil dates. The SQLite v1 to v2 migration rewrites any existing astronomical-era civil display string to the new BCE convention without modifying the underlying event instant.

## Now tick visual update
Now is represented exclusively by a short red tick extending left from the temporal axis; no horizontal line spans the event-name field and no red segment extends right of the axis. The tick updates every 250 ms while the Activity is resumed, disappears when outside the viewport, and continues to respect independent pan, zoom, and Now centering. The event ticks, hyperflow label layout, and connectors are unchanged.
## Continuous stack hyperflow
The invisible vertical viewport midpoint governs collision-free label placement; the moving left-of-axis Now tick remains independent. The solver uses exactly anchored, outward-packed layouts for adjacent chronological events and blends the valid layouts with a cubic continuous transition as the midpoint moves between their actual timestamps. An entire stack above the midpoint leaves its last (nearest) event straight; an entire stack below the midpoint leaves its first (nearest) event straight. Each unique-timestamp event becomes straight precisely when its own temporal anchor crosses the midpoint. In between, all affected labels bend and release continuously, without hard switching the nearest event or singular proximity weights. The blended results preserve minimum label spacing, stable chronological order, and local independence for noncompeting events. Labels at identical timestamps occupy a stable symmetrical row group. Extremely close distinct timestamps can still cause fast, but continuous, movement at extreme zoom-out; zooming in spreads the physical timestamp anchors. The temporal axis ticks and event instants never move.
## Gesture protection update
Pinch gestures now cancel the pending Android long-press on the first additional pointer contact, before the scale recognizer processes that contact. The full multi-touch sequence remains ineligible for editing until all fingers leave the screen, and dragging beyond the touch threshold cancels a pending long-press. Remaining-finger coordinates are rebased after a pinch to avoid sudden pan jumps. A fresh single-finger hold is required to edit an event. New JVM regression tests validate the long-press gesture gate.

## Controls
Vertical drag pans time; pinch zooms around the gesture center; horizontally drag over the text to read long single-line event names. The crosshair centers the current instant so the moving Now tick initially crosses the screen midpoint; after that it moves naturally while time advances. Tap the calendar to restore the current scale preset; long-press it to choose Day, Mean Synodic Month or Mean December-Solstice Year. Plus adds an event, long-press an event name to edit, and the info icon shows diagnostics. Long-press the title to reset horizontal text pan. A tied tick opens all events with that exact timestamp.
## Time models
Canonical event times use signed Unix epoch seconds and a nanosecond field. All dates use a proleptic Gregorian calendar. For Local with blank coordinates, the event's saved timezone is preserved when editing, even if the device timezone has since changed. For Local with coordinates, an offline geographic lookup selects a civil IANA timezone, then Android applies that zone's rules to the event date. The editor rejects daylight-saving clock gaps and requests an offset choice for overlaps. Longitude mode computes the precise mean solar offset longitude × 240 seconds, retaining fractional seconds. UTC always uses zero offset. Mean synodic month and mean December-solstice year are fixed reference zoom durations; no ephemeris data is used.
## Offline geographic timezones
The app embeds the publicly distributed BikepackPro timezone raster derived from timezone-boundary-builder 2026c and OpenStreetMap. Dataset version: 2026c, grid: 0.001°, zone lookup resolution approximately 111 m latitude. Dataset format: BPTZ v1; payload: 33,687,830 bytes; expected SHA-256 4f25382fa740a466f75444fc07a76dfce3150fa8a5d3455ba7e8e341d6e2a8b9. The first lookup copies the compressed APK asset to Android private storage and memory-maps it. Subsequent lookups require neither network nor location permission. Manually typed coordinates work without location permission; GPS is requested only when tapped.
The dataset is accurate near boundaries to approximately a 111 m grid cell, subject to upstream polygon uncertainty, and resolves geographic location as represented in 2026 rather than historical political borders. Android's timezone rules and some historical IANA mappings before 1970 may be incomplete; the app does not claim to reconstruct local civil clock law in 1493. Certain newer IANA identifiers are mapped to compatible legacy IDs for Android 8 support.
## Build in Termux
The source ZIP is small and does not embed the 33.7 MB third-party binary. On its first build, build.sh retrieves the pinned raster from the upstream attribution repository, verifies its SHA-256, caches it under ~/.cache/deep_timeline/tzraster_2026c.bin, and then bundles it inside the compiled APK. This first build requires Internet from Termux. Later rebuilds can run offline using the cached binary. To make a fully offline archive, place an existing, checksum-matching `tzraster.bin` file in the ZIP's `assets/` directory before building. No Internet permission is requested by the finished APK.
Requires an Android SDK platform android.jar, kotlinc, aapt2, zipalign, apksigner, Java, jar, keytool, zip, curl and sha256sum. The supplied build.sh compiles into a disposable temporary tree, reuses the earlier Deep Timeline signing key in Termux home to allow in-place upgrades, and leaves an APK at /storage/emulated/0/Documents/apk/Deep_Timeline_v20261108T180957Z.apk. The source ZIP belongs in /storage/emulated/0/Documents/zip/. Logs are written to /storage/emulated/0/Documents/log/. Rebuilding from this source ZIP does not use Gradle. To run JVM regression tests: bash test.sh. For signed builds, use bash deep_timeline_secure_build_v20261109T020314Z.sh; missing signing keys are fatal and are never regenerated.
## Privacy and data
Permissions are limited to foreground location access on explicit GPS use; the APK never requests Internet permission. SQLite event and viewport data live in Android-private storage. Uninstalling without backup removes events. Events may be backed up or imported with the native JSON document picker; an export template is also available.

## Quiet, compatible build pipeline
The stock Termux D8/R8 8.9.27 cannot interpret Kotlin 2.4 metadata, producing approximately 1.9 MB of misleading warnings while still reporting successful builds. The build downloads and caches Google R8/D8 9.1.29 at ~/.cache/deep_timeline/r8lib_9.1.29.jar, checks its reported version, and uses its D8 entry point directly instead of the old Termux d8 executable. Kotlin uses -nowarn to omit non-actionable deprecations in current Android APIs. Compiler stages capture output privately: success is summarized as RUN/OK lines, genuine warnings are preserved in Documents/log and summarized, and failed stages retain their complete output as deep_timeline_build_vYYYYMMDDTHHMMSSZ_<stage>.log. An incompatible Kotlin metadata warning is fatal, not hidden. All normal build logs remain at Documents/log/deep_timeline_build_vYYYYMMDDTHHMMSSZ.log. The first build requires an additional one-time official D8 download; later builds use the cache.

## Locality fix for independent event connectors
The previous cumulative-stretch solver used a global packed-origin offset. Crossing any dense cluster shifted that offset for every label, temporarily bending connectors belonging to unrelated, naturally spaced events. The replacement is a center-weighted monotone constrained projection: event labels retain their exact temporal anchors unless spacing conflicts force them to move. Crowded labels exchange displacement smoothly as they approach and leave the invisible center origin, while noncompeting labels remain exactly straight. A crowded cluster can still push its immediate neighbors when necessary, and that displacement stops where enough space becomes available. No nearest-event snap or new vertical text scroll is introduced. New locality regression tests cover independent events, inward and outward scrolling, and spillover into immediate neighbors.

## Longitude clock and scale-aware event visibility
A single local mean solar datetime is printed vertically, bottom to top, in the left gutter alongside the timeline axis. It represents the actual timeline instant at the vertical midpoint, translated by the observer longitude × 240 seconds. Tap the left gutter or long-press the Now icon to set observer coordinates manually or with on-demand GPS. The readout prompts for an observer longitude until configured. Unlike device civil time, longitudinal mean solar time never applies daylight-saving rules. The observer setting is separate from events and is saved in app-private preferences.
Event editor supports an optional maximum visible viewport span: enter any positive value and choose DAYS, MEAN SYNODIC MONTHS, or MEAN SOLSTICE YEARS. Events exceeding their zoom-out cutoff are entirely omitted from the current layout, including ticks and connectors, but stay in the database and return on zoom-in. Thresholds are inclusive. In the Event Data menu choose SET EVENT VISIBILITY LIMITS to use the event checklist for bulk assignment. Existing events without thresholds remain visible at every scale. Visibility limits survive JSON import/export and the v2-to-v3 SQLite migration. See docs/Visibility_And_Observer_Time_v20261108T180957Z.md.

## Fixed viewport-center readout
The left-gutter longitudinal date-time is rotated bottom to top and centered on the actual vertical midpoint of the timeline view. Text placement uses the same Canvas pivot for rotation and drawing, with a font-metrics baseline and a fit-to-height fallback for shorter viewports. With no observer longitude configured, the display shows UTC with SET LONGITUDE instead of falsely labeling it local mean time. Tap the readout or long-press Now to configure observer longitude.

## Exact visibility thresholds and searchable hidden events

Use `1/3`, `2^10`, `2^-3`, `2^10/3`, `1.5e-4`, `0.(3)`, or `2⁷` in a visibility amount. Values are exact rational expressions; fractions with repeating decimal expansions remain fractions, not truncated decimals. Units remain mean days, synodic months, and December-solstice years. Event JSON `maxVisibleSpan.value` is a quoted string and round-trips unchanged; format version 1 remains valid. Tap DEEP TIMELINE or use Event Data → Search All Events to find any event including hidden ones, then tap an event to center and zoom to an appropriate scale.

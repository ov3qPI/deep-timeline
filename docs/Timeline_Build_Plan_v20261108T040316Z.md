# Timeline — Revised Native Android Build Plan
Version: 20261108T040316Z
Status: design specification; no APK or source implementation included
Supersedes: Timeline_Build_Plan_v20261107T210134Z.md
## Product definition
Offline-first native Kotlin timeline for Android. Pure black (#000000) and pure red (#FF0000). A fixed vertical temporal axis on the left supplies exact chronological anchors. A right-hand label field displays event names as individual, unwrapped lines. Bent connectors link exact time-axis anchors to labels only while the associated label is onscreen. The physical timeline alone governs vertical navigation: there is no independently vertically scrolling text list.
## Interaction contract
- Swipe vertically anywhere outside controls/editor to pan the temporal center. Earlier dates are above; later dates below.
- Pinch vertically or diagonally to zoom continuously about the pinch's temporal focal point. Remove the arbitrary 30-second minimum full-screen span. No app-defined maximum magnification; stop only when requested precision exceeds the canonical timestamp resolution or hardware/numerical representability. Represent zoom in logarithmic form, clamp exponential conversion to safe finite values, and avoid precision loss through epoch-relative integer subtraction.
- Horizontally swipe in the text region to pan the entire text/connector scene as one layer while keeping the temporal axis and its ticks pinned to the left. No word wrap; let the longest names extend arbitrarily rightward. Horizontal state is independent of temporal center and zoom. Provide direction-aware gesture arbitration: vertical displacement changes time, horizontal displacement changes readable text position; pinch takes priority when a second pointer arrives. Keep horizontal pan within sensible bounds from measured text widths, with option to reset to the normal label origin.
- The Now icon centers the current instant without changing zoom or horizontal text pan. The moving left-of-axis Now tick then advances in time relative to that fixed viewport center.
- Tap the Scale icon to set full viewport height to the selected reference interval while preserving the current center instant. Initial preset Day. Long-press the icon for Day, Mean Synodic Month, and Mean December-Solstice Year. Selected preset persists, but free pinch modifies zoom without moving center. An optional fit-all command may be added separately rather than treating it as a hard zoom-out limit.
- Plus opens Add Event. Long-press a visible event name opens the identical editor with the event loaded. Trash cancels an unsaved new event or confirms deletion of an existing event. Save persists changes atomically.
- The event whose true timestamp is closest to the instant at vertical viewport center is the focused event. Focus identification does not itself snap, shift, or reorder labels; it is derived from continuous center time. Equidistant timestamps use a deterministic stable tie-breaker. The Now reference line is placed at the real-time instant rather than the viewport center; it updates every 250 ms in the foreground and disappears if Now is outside the viewport. The center is a mathematical focus and panning reference, not a drawn line.
## Anchor and label geometry
- The temporal axis is a constant device-space x position. Each event has exact anchor y = H/2 + deltaTime / secondsPerPixel. Each label additionally has a screen-space solved y coordinate and a horizontal position derived from the horizontal pan. DeltaTime must be computed at high precision before conversion to a limited viewport-sized Double.
- Sort labels by (instant, stableId). Use a center-weighted minimum-gap isotonic projection: labels preserve their exact event anchors unless a spacing constraint forces movement. Nearby competing labels push and release one another with continuous weights derived from their distance to the invisible midpoint. Unrelated free-standing events stay straight. Do not use a cumulative packed-field offset, which shifts independent labels when a distant cluster crosses the midpoint. No nearest-event choice or snap influences label geometry. Use incremental/windowed layout as performance requires.
- Draw a short right-hand tick for each event whose *anchor* falls in the viewport, even when its associated label is pushed above or below screen bounds. When a label is vertically offscreen because of density, omit its connector entirely: do not leave a dangling segment toward a screen edge. Its tick remains visible at the actual time-axis position.
- When anchor and label are onscreen, draw a smooth connector with its first endpoint attached to the true anchor and its second endpoint attached to the label. A connector may shift dramatically or bend as density changes, but anchors never move in time. Clip horizontal connectors/text to the viewport as the user pans right to read long names. No layout is allowed to change event times.
- When an anchor falls outside the viewport, do not draw its tick. If its displaced label remains visible, treat it with a conservative offscreen-connection affordance instead of falsely attaching it to a different time; the exact behavior must be visually tested. Names/records are never discarded by density, even when not currently visible on the finite display.
- Multiple events at exactly one timestamp have intrinsically coincident anchors at every zoom level. Keep their records and stable ordering, render their shared tick, and enable selecting/cycling through their labels from that tick as an exceptional disambiguation interaction. Zoom alone cannot separate identical instants. Prefer keeping tied labels grouped and avoid cluttering every tick with an extra count indicator.
- Virtualize Canvas drawing using temporal indexing and label-layout spatial indexing. All records remain persisted and addressable; merely offscreen geometry may be culled. Stress test clusters of 1,000–10,000 events, long text, unicode, and identical times. No separate text scroll pane.
## Reference time scales: no ephemerides
- Day = exactly 86,400 elapsed seconds; this is not a civil midnight-to-midnight day when daylight saving changes.
- Mean Synodic Month = 29.530588853 × 86,400 elapsed seconds, a representative mean period rather than actual conjunction-to-conjunction duration.
- Mean December-Solstice Year = 365.24274 × 86,400 elapsed seconds, a representative solstice-to-solstice duration near epoch 2000, not a true solstice boundary calculation. This is intentionally distinct from the generic mean tropical year (~365.24219 days).
- Scale button sets secondsPerPixel = selectedDurationSeconds / usableTimelineHeightPx and retains current center time. Calculations use a high-precision decimal or carefully managed Double for viewport scale; target numerical error substantially below one pixel at 4,000-pixel test height. Do not promise actual new moon/solstice boundary coincidence: the model purposely discards that astronomical precision.
- No astronomical data files, network requests, ephemeris engines, modeled events, or temporal-range restrictions for presets.
## Data model
- Store event UUID, unwrapped name, signed epoch second, nanosecond fraction, original civil timestamp fields, chosen mode, original coordinate pair if supplied, resolved IANA zone ID or exact longitudinal offset, offset-resolution metadata, and update/version metadata. Use a composite database index (epochSeconds, nanos, UUID), all written in transactions.
- Canonical instant is the universal temporal ordering authority. Store as signed seconds plus nanos, not a floating-point Unix timestamp. Expose a portable UTC-like timestamp string for interchange; explicitly use a proleptic Gregorian convention for historical dates (UTC itself was not a contemporaneous civil standard in 1493). Do not call an event in 1493 historically verified local civil time merely because it maps to a modern zone ID.
- Viewport state persists separately: center instant, logarithmic zoom, horizontal pan, selected scale, and optional focused event ID. Changing device timezone, GPS state, or app process cannot silently shift a stored instant.
## Unified event editor
- Simple Name, Date, and Time inputs, including seconds and optional fractional seconds. One timezone mode selector with Local (default), UTC, and Longitudinal. Save plus compact trash icon. Same editor for add/edit.
- Selecting Local or Longitudinal reveals a coordinate field supporting pasted latitude/longitude in decimal degrees (including signed values and common N/S/E/W syntax), with a GPS vector icon on the right. The GPS icon actively requests a location fix after an explicit tap; no launch-time or background GPS access. Show fix age/accuracy when using a cached fix. Typed coordinates never trigger location permission.
- UTC interprets typed wall time as zero-offset. It does not need coordinate input.
- Local interprets typed wall time using the civil IANA timezone identified by the entered coordinate. A coordinate-to-zone resolver requires a bundled offline geographic timezone boundary index, separate from Android's existing IANA time conversion rules. Resolve a zone ID first, then apply the zone's rules for the specific typed event date; do not derive it by merely rounding longitude or silently using the phone's own timezone. Handle DST overlaps by asking which offset is intended and DST gaps by requiring correction.
- For default Local mode when the coordinate field is empty, explicitly show the device's current timezone as the fallback and allow saving without GPS. When the user enters coordinates, the coordinate-derived zone overrides this fallback and the selected source remains visible. If the polygon lookup fails or the location is close to a contested boundary, require explicit user selection of an IANA zone rather than guessing silently. Historic timezone boundaries and pre-1970 offsets may be incomplete or unreliable; communicate this where relevant, and save the exact interpretation selected.
- Longitudinal interprets wall time at offset = longitudeDegrees × 240 seconds east of Greenwich, with signed decimal precision. Latitude does not enter the offset calculation. This is longitude-derived mean solar time, not modern legal civil time and not apparent solar time including the equation of time. Avoid Java ZoneOffset's integral-second restriction by doing exact decimal offset arithmetic before constructing the canonical instant. Save the original longitude rather than a transient GPS read.
- Editing loads the original mode, coordinates, civil fields, and zone interpretation exactly; saving intentionally recomputes the canonical instant only if relevant fields change.
## Permission, persistence, and diagnostics
- Location permission only if GPS icon is used. No background location permission; no internet permission in initial build. Manual coordinates work offline without permission. Database stored in Android private app storage. Export/import is a possible subsequent feature.
- Diagnostics screen contains app/script identifier and version, OS/API version, event counts, center instant, seconds/pixel and chosen preset, measured frame/layout timing, saved timezone resolver version, device timezone, GPS permission/fix state, and a Copy to Clipboard control.
- Pure-red-on-black native widgets, manually styled where platform color theming would introduce additional hues. Consider anti-aliased edges as raster blending rather than separate UI palette choices.
## Source and no-Gradle Termux packaging
- Native Kotlin Activity, custom Canvas View, gesture detectors, SQLite, java.time, optional LocationManager for GPS, and bundled compact geographic timezone index. Keep external dependencies minimal; prefer Kotlin/Java platform APIs and pre-generated offline geographic data. No Rust unless profiling justifies it.
- Build via installed Kotlin compiler, JDK, aapt2, d8, zipalign, and apksigner; not Gradle. Zip contains sources, resources, packaged runtime dependencies, data index, and self-contained shell build script. Build unpacks to a disposable directory in Termux home; successful build copies signed APK to /storage/emulated/0/Documents/apk/, copies versioned ZIP to /storage/emulated/0/Documents/zip/, removes staging, and invokes Android package installer. Failed builds preserve logs and do not invoke installer.
- Scripts include a UTC _vYYYYMMDDTHHMMSSZ identifier. App version appears in diagnostics. No source comments or empty lines; minimize unnecessary line breaks.
## Delivery phases
1. Core native shell and precision-based temporal model: black/red Canvas, axis, true ticks, now/scale/plus controls, persistent center/zoom, SQLite, initial add/edit/delete.
2. Layout engine: monotone rows, nonwrapping labels, dynamic connectors, disappearing offscreen connectors with surviving anchor ticks, stable focus, identical-timestamp disambiguation, viewport virtualization.
3. Navigation: arbitrary high magnification limited only by timestamp resolution, pinch focal preservation, vertical timeline scrolling, independent horizontal scene pan, proper gesture arbitration, fit-all action if wanted.
4. Scales: exact 86,400-second Day and mean month/year reference presets, long-press menu, 4,000-pixel precision checks, no ephemeris.
5. Coordinate-aware editor: manual coordinate parsing, explicit GPS acquisition, offline coordinate-to-IANA resolver for Local, fractional longitudinal offsets, DST overlap/gap controls, historical-data caveats, saved provenance.
6. Diagnostics and delivery: profiler copy-out, real-device stress tests, no-Gradle versioned ZIP and signed APK, disposable build/install command and regression tests.
## Acceptance tests
- With viewport center held fixed, the Now tick advances 1 px for each 0.25 seconds at scale 0.25 seconds/pixel; when Now is outside the visible temporal range, the tick is not drawn; no fixed screen-center reference line is present.
- Now refreshes every 250 ms only while the Activity is resumed; no Now redraw should initiate an event-label recomputation unless the geometry changed.
- 1,000 events inside one second: increasing zoom spreads distinct timestamps so their names become steadily easier to read; no imposed 30-second floor; no focus-triggered visual snapping.
- 1,000 events sharing an identical timestamp: coincident anchor stays correct; each event remains accessible through the tie interaction; zoom does not fabricate separation.
- A dense cluster pushing labels out of the screen: all corresponding onscreen anchors retain rightward ticks, while lines to vertically offscreen labels are fully suppressed.
- A 50,000-character name stays in one line, can be read through horizontal scene pan, and does not shift time position or enable a separate vertical list scroll.
- Scale tap at year 1493 adjusts only viewport height to the mean selected duration, never requests ephemeris, and never changes center instant.
- Two events on either side of the center: nearest one changes focus at the mathematical midpoint, without changing label positions by an arbitrary jump.
- Pasted coordinates resolve appropriate present-day IANA zones offline; wrong or disputed zones can be manually corrected. Longitudinal offset yields correct sign and subsecond component; UTC is coordinate-independent.
- With Local mode, ambiguous/nonexistent DST times cannot be silently converted; historically unreliable dates are not represented as verified geographic civil time.
- Rebuild from project ZIP in Termux without Gradle; produce versioned signed APK and diagnostics with Copy to Clipboard.

## Implementation update — 2026-11-07
Local with no coordinates automatically uses the Android device timezone. Local with coordinates automatically uses a bundled, offline 2026c OpenStreetMap-derived BPTZ 0.001-degree geographic timezone raster; a manual override remains available for edge cases. The source-only ZIP downloads the pinned raster at first Termux build, verifies SHA-256 and packages it into the APK. The APK itself needs no Internet permission. See the implementation README and THIRD_PARTY_DATA.md for provenance and historical limitations.

## Elastic center-anchored text placement
Do not choose the nearest event as a special unmovable reference. Instead solve for ordered collision-free label positions by projecting true temporal anchors onto minimum-gap constraints with continuously changing center-proximity weights. Each event has zero displacement unless a competing label actually needs its space. In a dense stack, the event closest to the invisible screen center naturally receives the greatest stiffness; as the center moves, the weights change continuously and rows flow. Exact timestamp ties occupy symmetric rows. The local projection keeps independent, noncompeting event labels straight even while a dense group elsewhere changes position. When density relaxes during zoom, displacement becomes zero. The Now line is separately positioned at wall-clock time every quarter second.

## Continuous stack hyperflow update
The previous reciprocal-distance weighted isotonic solver became numerically over-sensitive when the screen center approached an event anchor: a weight could dominate the entire compressed block abruptly. Replace that process with two independently feasible, chronological center-pinned packing solutions and interpolate continuously between them. At the top and bottom of a stack, respectively the first and last closest-to-center event is exactly straight. At a precise event/center coincidence, that event is straight. Between two distinct event anchor times, interpolate their fully packed solutions using cubic smoothstep with zero endpoint velocity; this avoids a hard pivot threshold and keeps all adjacent label baselines at least the configured minimum gap apart. Events outside a collision chain stay on their original temporal coordinates. Equal-instant events are represented by a stable symmetric tied block. Inherent tradeoff: if many unique timestamps occupy only a tiny number of pixels, exact straightness at every successive event crossing requires a proportionally fast but continuous visual flow. Users may zoom closer to reduce that speed. The left-of-axis Now tick remains independent and continues refreshing every 250 ms. Regression coverage includes a 15-item cluster entering and leaving the center, subpixel center crossings, timestamp ties, label separation, and isolated event straightness.

## Now tick rendering update
Remove the screen-width horizontal Now line entirely. When the absolute Now instant is within the viewport, draw only a short two-pixel-stroke red horizontal tick extending 16 density-independent pixels to the LEFT from the temporal axis, ending precisely at the axis. Use the same actual Now screen coordinate and foreground redraw every 250 milliseconds while resumed. Do not draw a segment right of the axis. Event ticks, their connectors, and continuous hyperflow behavior are unchanged. Now outside the viewport renders no tick.
